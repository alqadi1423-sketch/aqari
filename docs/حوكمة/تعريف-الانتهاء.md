# تعريف الانتهاء

> **مصدره:** رسالة المالك «الخطة والقواعد · ومرحلة التثبيت» (2026-10-07).
> البند لا يُعدّ منتهياً إلا إذا اجتمعت الشروط الخمسة كلها. وما ينقصه شرطٌ يُكتب في [الخطة.md](الخطة.md) «مرفوعاً، ينتظر …» لا «منتهياً».

## الشروط
1. **الاختبارات كاملة تنجح على ويندوز ولينكس.**
   - **ويندوز (جهاز البناء):**
     - `npx tsc --noEmit` بلا خطأ؛
     - `npx jest` كاملة؛
     - ومجموعة المحاكي:
       ```bash
       firebase emulators:exec --only firestore,storage --project demo-aqari "npx jest -i --testPathPattern emulator"
       ```
   - **لينكس:** تشغيل GitHub Actions (`.github/workflows/tests.yml`) على الالتزام نفسه، وخلاصته في فرع `ci-results`:
     ```bash
     git show origin/ci-results:latest.txt
     ```
   - **لا يُقبل** اختبار متخطّى أو معطَّل لأجل البند.
2. **مراجعة مستقلة.**
   - يجريها وكيل بسياق جديد لم يكتب الكود.
   - نتائجها بالخطورة والدليل.
   - لا ملاحظة حرجة أو عالية مفتوحة.
   - والمستقل نفسه يتحقق من الإصلاح.
3. **قائمة اختبار على الجوال نجحت عند المالك.**
   - الحزمة على فرع `apk` (موقّعة بمفتاح الإصدار، arm64-v8a وحدها).
   - ومعها قائمة اختبار عربية لكل ما تغيّر.
   - والمالك يبلّغ بنجاحها.
4. **موافقة المالك** على البند نصاً.
5. **التوثيق محدَّث.**
   - `docs/DESIGN.md` في موضع البند.
   - و[سجل-القرارات.md](سجل-القرارات.md) بكل قرار يخصه.
   - و[الخطة.md](الخطة.md) بحاله.

## ما لا يُعدّ انتهاءً
- **«مبنيّ ومختبَر»** بلا قائمة الجوال وموافقة المالك.
- **نجاح الاختبارات على ويندوز وحده.**
- **إصلاحٌ بلا اختبار** يفشل قبله وينجح بعده.
- **إصلاحٌ في بيانات المالك** بدل التطبيق: كل إصلاح يُبنى في التطبيق ليعمل لأي مستخدم.
